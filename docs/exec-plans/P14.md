# P14 - Visualization / HPC / Release Candidate (scope)

Date: 2026-09-14. Depends on P13 (the mechanism cards) and everything before it: the kernel, the
sandbox, the experiments, the calibration, the evidence registry and the cards.

## What this phase does

Make the model **runnable, observable and portable to HPC without changing a single mechanism**. That
last clause is the constraint the phase is judged on: P14 adds no rule, no parameter, no state
variable and no tick-order entry. It adds surfaces over what P01-P13 already produce.

```text
CLI           run · replay · experiment · calibrate · analyze · doctor · bench · batch
UI            county nodes · migration · trade · armed groups · time series · compare · mechanisms
HPC           task plan · one task per array index · independent seed and manifest · merge
reproducible  a declared demo scenario whose digest a regression test reproduces
performance   a measured benchmark with declared dev and HPC thresholds, and a profile
docs          quick start · architecture · epistemic warning · reproduction · HPC guide
release       tag v0.1.0-rc1
```

## Non-goals

- No new mechanism, rule, parameter, subsystem or tick-order entry.
- No LLM on a compute node, ever, and no API key anywhere near the batch layer.
- No network requirement on a compute node: the runtime LLM's decisions, if a large experiment ever
  needs them, are **recorded in a networked environment first** and replayed from fixtures on the
  cluster (§HPC below).
- No UI before mechanism validation (P00's rule 20): the UI is read-only over artifacts, and it is
  built now precisely because P13 validated the mechanisms.
- No new dependency, and no configuration file for a threshold that a constant states plainly.

## HPC principles the phase implements

```text
compute nodes need no network by default        the batch layer's import graph has no transport
no API key is uploaded                          env_checks warns by name, never prints a value
no USTC runtime LLM on HPC                      USTC_LLM_ENABLED=0 is written into the Slurm template
recorded decisions replay on the cluster        FixtureStore + ReplayTransport, generated online
every Slurm task has its own seed and manifest  seed = base_seed + array index, written per task
a failed task can be re-run                     tasks are idempotent and failure-isolated
```


## Performance thresholds

Two declared sets, because the two environments answer different questions:

```text
dev   one core, a laptop           enforced by late-ming-lab bench --enforce
      the numbers below come from what P14 measured on this machine, with headroom
hpc   one Slurm array              declared as a budget: per-task cost × tasks ≤ walltime × safety
      the template derives its walltime from the measured per-task cost, not from a guess
```

The dev thresholds are checked against a measurement the phase actually made; the HPC budget is a
declared target for sizing the array, and the phase says so rather than pretending a cluster was
available to validate it.
