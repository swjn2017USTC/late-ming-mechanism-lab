# P11 — USTC DeepSeek V4.1 Institutional Decision Layer (scope)

Date: 2026-09-14. Depends on P00's boundary contract (`docs/architecture/runtime-llm-boundary.md`),
P01's tick order (which reserved `INSTITUTIONAL_DECISIONS`) and P07's sandbox.

## What this phase does

Implement the runtime decision layer the boundary document has specified since P00, and keep it
inside its fences.

1. **The interface.** `InstitutionalPolicy.choose_action(observation, action_space)`, with the
   observation anonymized and audited, the decision Pydantic-validated, the action space bounded per
   role, and every action mapped to a declared lever.
2. **The runtime policy.** `USTCV41Policy` over an OpenAI-compatible USTC endpoint: no tools, a
   structured prompt, a validated answer, a timeout, retries on transport failures only, explicit
   429 handling, prompt and response hashes, model id logging, and a gate that refuses any model but
   the operator-confirmed DeepSeek V4.1 — *before* a credential is read. No fallback of any kind, and
   the forbidden ids (V4 Pro, legacy V4 Flash, Qwen, GLM, OpenCode Go, OpenAI) are named in the
   refusal.
3. **The declared alternatives.** Rule, utility and random policies, so that "fail closed, or switch
   to an explicitly declared rule-based policy" is a real option rather than a phrase.
4. **Recording and replay.** A live answer is sanitized into a fixture (no account ids, timestamps,
   usage or fingerprints) and replayed deterministically; a replay miss is a refusal, never a
   synthetic answer.
5. **The seats.** Four roles — central fiscal, provincial, county, armed-group leadership — occupied
   by a handful of actors, triggered by *crossings* of declared reading lines rather than by a
   schedule, at most one decision per tick and never twice within twelve months.
6. **One smoke scenario.** A short run proving the chain end to end, with a decision trace that
   records the model, the prompt hash, the answer hash, the action, the intensity and the levers.

## Non-goals

- No large LLM experiment, no LLM-driven physics: the model never produces harvest, price, revenue,
  death, migration, battle or recruitment numbers, and no rationale ever reaches world state.
- No new mechanism, rule or parameter value; the only model change is two declared setters that let a
  decision reach the extraction policy and the relief share.
- No runtime LLM in tests: the default suite is offline, the live suite is opt-in and marked.
- No credential handling beyond the transport, and the key is never read, printed or committed.

## Acceptance criteria

```text
the interface with a bounded action space per role · structured input, anonymized and audited ·
structured output, Pydantic-validated · one confirmed model id, exact match, no fallback ·
credential read only after the gate · no tools in the payload · timeout · retries only on
transport failures · explicit 429 handling · prompt hash, response hash, model id per decision ·
reasoning cannot modify state · recorded fixture replay · event-triggered seats for four roles ·
a smoke scenario · @pytest.mark.live_ustc opt-in and the default suite offline · no USTC call
without a confirmed model
```
