# V2.1-P11 — Two Decisive Contrasts (exec plan)

Run against `docs/OMP_UPGRADE_PLAN_V2_1.md` §V2.1-P11. No V2.1-P12 work starts in this phase.

## Entry condition

**Satisfied.** `docs/phase-reports/V2.1-P10.md` establishes, from the artifacts, that the historical
core is `deterministic-replay-by-design`: 40/40 P05 logs record the draw-free
`observed-historical` forcing, the only tick-path system that can consume RNG is the climate model,
and no declared design document names another stream as consumed. There is no RNG wiring blocker, so
a contrast run at **one seed per arm** is a complete sample and not a sample of one: the run has no
randomness to average over. Every seed beyond the first would be a replay, and P10 forbids counting
one as a replicate.

## The two questions, frozen before any run

### M002 — crisis gating on the historical core

The card (`docs/mechanisms/v2/M002.md`) rests on the gate at
`src/late_ming_lab/systems/migration.py#_permanent_gate`, and its own uncertainty says "the
historical core's own gate contrast has not been run". This phase runs it.

| | arm | declaration |
| --- | --- | --- |
| A | `reference` | the historical core, every chain and rule at its neutral value — the same declaration as P05's `reference` arm |
| B | `gate-open` | the same input with **only** the mobility gate opened: the parameter updates of the project's declared `OPEN_MIGRATION_EXIT` intervention (`experiments/interventions.py::_open_migration_exit`), applied to the historical core — migration costs, transit loss and minimum move to the open values, and the two household unmet-ratio lines to zero |

No existing run answers it. The V2-P03 pilot's `OPEN_MIGRATION_EXIT` arm is the sandbox baseline (toy
dataset, synthetic climate, declared disruption and escalation regimes), not the historical core, and
its configuration differs from the historical core's in the dataset, the forcing, the disruption
regime and the extraction policy. Reusing or renaming it would report a different experiment as this
one, so it is **not** reused. P04's `migration-distress-route` opens the *destitution* route
(`destitution_departure_share`), which P04 itself describes as a bypass of eligibility and silver
rather than the eligibility line, so it is a different gate and is **not** reused either.

**Primary reading, continuous, read first:** the assessable base, whole-run window, both the
protocol's `fiscal_base` outcome (`tax_base_change_mu`, `tax_base_end_mu`) and the governance
indicator `tax_base_contraction` = `(base_start − base_end) / base_start`. Absolute value per arm,
the paired difference `gate-open − reference`, and the relative difference.

**Secondary reading (the threshold projection), read after the continuous comparison is computed and
recorded:** the derived `breakdown` reading — the share of the frozen 50,625-member threshold
ensemble under which each arm reaches breakdown, at every crossed count the protocol allows
(4…8). Breakdown is an additional reading and never the headline.

**Falsifier, verbatim from the card:** "A run in which the gate arm's tax base contracts no further
than the baseline's would falsify the mechanism."

**Pre-registered status rule (from the upgrade plan):** M002 keeps `CONDITIONAL` only if the
historical-core gate arm's continuous contraction differs from the reference *in the pre-registered
direction* and by at least the protocol's `fiscal_base` minimum substantive effect (0.02, on the
relative change the protocol declares for that outcome). If it does not, the card is downgraded to
`WEAK`, or `REJECTED` if the falsifier fires (the gate arm contracting no further than the
reference). **No status is decided from `breakdown`.**

### M004 — elite accumulation against closed credit

The card (`docs/mechanisms/v2/M004.md`) states its own falsifier and says that the comparison "has
not been measured"; V2 measured the branch firing (51 foreclosures in one replicate) and nothing
else.

| | arm | declaration |
| --- | --- | --- |
| A | `elite-credit-closed` | `EliteParameters.loan_to_value = 0.0` — the project's declared `NO_ELITE_CREDIT` ablation (`experiments/interventions.py::_no_elite_credit`), V1's own null for this mechanism |
| B | `elite-accumulation` | `foreclosure_after_unserviced_months = 1`, `foreclosure_land_share_of_pledge = 1.0` — the P05 declaration, unchanged |

**Primary reading, continuous:** the assessable base for both arms (same two measures as above) and
the paired difference `accumulation − credit-closed`.

**The chain, read beside it:** `ELITE_LOAN` rows, `ELITE_DEFAULT` rows, `ELITE_FORECLOSURE` rows with
Σ`mu_transferred`, Σ`pledge_mu` and Σ`settled_tael`, and the land the transfer moved. A branch that
fires is not an effect comparison, and the 51-foreclosure count is reported as what it is.

**Falsifier, verbatim from the card:** "The accumulating branch should contract the assessable base
further than the closed-credit arm; if it does not, the bifurcation has no second branch and the card
should say so in one sentence."

**Pre-registered status rule:** M004 rises from `WEAK` only if the accumulation arm's contraction
exceeds the closed-credit arm's by at least the declared minimum substantive effect **and** the
foreclosure/land-transfer chain is non-zero. Otherwise it stays `WEAK`, or is downgraded if the
falsifier fires. M001, M003, M005 and M006 are not touched.

## Non-goals

- No `docs/v2/**`, `outputs/v2/**` or V1 artifact is written, rewritten or re-scored.
- No outcome, threshold band, hold-out window, historical input or core state transition changes. The
  frozen protocol and the frozen threshold ensemble are read, never edited.
- No reserved window is scored: the contrasts read `whole-run` under `purpose="report"`, and the
  calibration and hold-out windows are not read at all.
- No seed is treated as an independent replicate (P10), no calibration or sensitivity ladder runs, no
  runtime LLM call, no new dependency, and no other mechanism card's status moves.
- The contrasts are **not** extended to a second seed, a third arm per question, or a resolved
  threshold question: the phase's budget is four trajectories and the pre-registration is fixed
  above, before the runs.

## Acceptance criteria

1. Four trajectories at most, one per arm, at one declared seed; each carries its configuration
   diff, its trigger chain, a no-op verdict from the existing detector, and complete provenance.
2. The `reference` arm reproduces `e856aa13b75c0664…` / 247,110 events (P05's reference), and
   `elite-accumulation` reproduces P05's accumulation arm digest at the same seed — otherwise the
   contrast is not the one it claims and the phase says so rather than proceeding.
3. M002 reports the continuous base readings **before** the threshold projection, and the projection
   is reported at every allowed crossed count.
4. M004 reports the paired base difference **and** the foreclosure/land-transfer chain; no status is
   proposed from a branch-firing count.
5. Each status recommendation quotes the pre-registered rule and the falsifier it was tested against,
   and names the alternative it rejected.
6. Every number in the documents is read through a typed accessor; none is typed by hand.
7. `outputs/v2/**`, `docs/v2/**` and the frozen protocol files are byte-identical after the phase,
   and `python -m late_ming_lab.release verify` still reports 0 drift.

## Failure conditions

- **Budget.** Simulation wall clock over 10 minutes: stop, keep the artifacts already written, and
  report the overrun. Four 240-tick historical-core runs are ≈45 s in total, so this is a stop rule
  rather than an expectation.
- **Cross-check mismatch.** If the `reference` arm does not reproduce P05's digest, the tree's
  mechanism path has moved since P05 and the contrasts are not the ones the cards were written
  against: report it and stop before recommending any status.
- **No-op.** An arm that declares a structure and moves nothing against the reference is a failed
  arm, not a null result: the detector refuses it and the phase reports the refusal.
- **Missing artifact.** A run directory, manifest or log the accessor declares is absent: report it as
  absent. Absence is not zero.
- **A status rule that cannot be applied.** If a reading the rule needs was refused by the protocol's
  missingness rule, the status is not proposed; the refusal is reported instead.
