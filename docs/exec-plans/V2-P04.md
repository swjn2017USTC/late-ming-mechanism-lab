# V2-P04 — Failed Hold-out Mechanisms

Exec plan for `docs/phase-reports/V2-P04.md`, written before this phase's results were read. It
follows `docs/v2/phase-conventions.md`, implements `docs/OMP_UPGRADE_PLAN_V2.md` §6 (V2-P04) and its
prompt (`docs/OMP_UPGRADE_PROMPTS_V2.md` § "Prompt 4"), and is scored under the protocol frozen in
V2-P03.

## Why

V1's reserved windows failed in four places, and a failure is only useful once it is attributed:
to the data, to the observation function that reads it, to a parameter, to a structure, or to nothing
this model can currently decide. The phase diagnoses all four, builds the instrumentation that makes
the chains behind them visible, and runs competing structures on the *same* historical input and the
*same* world seeds — because a variant that is not contrasted on identical inputs, or that turns out
to change nothing, is not an experiment.

## The four failures, and what is known before running anything

| V1 check | window result | where it points |
| --- | --- | --- |
| `shock-peak-in-late-years` | hold-out 0.00, whole-run 0.00 | the synthetic forcing: severity is uniform, so the worst year is anywhere |
| `price-spike-peak-late` | hold-out 0.44, whole-run 0.44 | the price rule: one rule, one operating point, and same for dispersion |
| `dispersion-widens`, `dispersion-tracks-distress` | 0.44, 0.38 | as above |
| `relief-coverage-falls-as-need-peaks` | hold-out 0.25, extrapolation 0.00 | coverage is a ratio of two aggregates; which bottleneck binds is invisible |
| `exits-in-crisis-years` | hold-out 0.16, extrapolation 0.00 | the departure gate: a household needs silver to leave, in a famine |

## Scope

1. **A diagnosis per failure**, `docs/v2/hold-out-diagnosis.{md,json}`, generated from artifacts:
   classification (`data` / `observation` / `parameter` / `structure` / `undetermined`), the numbers
   that support it, and the unresolved boundary that remains after the phase.
2. **The chains made visible**, in the event log rather than in a report's arithmetic:
   - price: stock, unfilled demand, trade capacity, transport cost and the price bounds, each
     recorded as its own constraint per node-month, with which one bound;
   - relief: granary stock, treasury silver, relief logistics capacity and eligibility, likewise;
   - migration: temporary, permanent, in-region, out-of-region, destination capacity and transit
     loss, with the gate that refused each move.
3. **Competing structures on historical-core-v1 at identical world seeds.** At least two, each with a
   named ablation of its own new parameter, each run at the same seeds as the reference:
   - a demand-pressure price structure, where the posted price responds to demand the stock could not
     meet, against the inventory-only rule V1 has;
   - a need-gated migration structure, where departure is a distress decision with destination
     capacity and transit loss, against V1's silver-gated move.
4. **Named parameters with cards**, in `data/parameters/v2_holdout.yaml`, graded honestly (`S` where
   nothing constrains them) and listed for the V2 sensitivity pool.
5. **Scoring under the frozen V2-P03 protocol**, on the primary outcome vector and the mechanism
   statuses, with the hold-out checks reported beside it and never used as the only criterion.
6. **Observed against synthetic forcing** as one declared contrast, with no adjustment of the
   observed series toward any target.

## Non-goals

- No tuning of the observed climate series, no re-fitting of V1 parameters, no new historical claim.
- No V2-P05 work: no famine-mortality variant, no elite-mediation variant, no new actor.
- No *silent* change to a declared pin. This plan expected the pins to hold, and they did not: the
  chain events lengthen the log, so the digests moved. The rule the repository states for that case
  is followed instead — re-pin deliberately, in the commit that changes the vocabulary, and record
  the row-level difference in the phase report. It is recorded in `data/scenarios/historical-core-v1.yaml`,
  `data/scenarios/demo.yaml` and `tests/regression/test_integrated_regression.py` with the reason
  beside the new value; the reference arm reproduces the new pin, and the phase report shows that the
  only rows added are the three chain events while every behavioural count is unchanged.
- No threshold in V2-P03's protocol is moved to make a check pass; the ensemble is applied as frozen.

## No-op detection

Every arm must prove it intervened: a non-empty configuration diff, a named parameter that moved, and
at least one event count or intermediate series that changed at the same seeds. The phase runs a
deliberate no-op control (the new parameters at their neutral values), and a detector that must refuse
it; if the detector accepts it, the phase fails.

## Amendment, after the review

An independent reviewer found three things this plan got wrong or left open, and all three were
addressed before the commit rather than deferred: a declared budget for parameter provenance (each arm
now writes `holdout-arm.json` beside its run, because a run directory did not otherwise record which
parameters built it), the armour around the no-op detector (duplicate arm labels are refused, the
reference arm must be the neutral one, and an ablation whose diff is non-empty is refused), and the
relief failure's classification, which the model-side numbers support as **structure** rather than
observation. The plan's own non-goal about pins is amended above.

## Acceptance

- Every V1 failure has an artifact-backed classification and a stated unresolved boundary.
- Two competing structures ran on historical-core-v1 at the same world seeds, and the comparison is
  provable from the configuration diff, event counts and intermediate series.
- Any no-op arm fails the detection that the phase ships with.
- `tests/invariants`, `tests/regression`, `ruff`, `mypy` pass with real output in the report; an
  independent review looks for a variant that does not actually intervene, a check read as a result,
  and a threshold moved to flatter the hold-out.
- `docs/phase-reports/V2-P04.md`, logical commits, clean tree, STOP. V2-P05 is not started.
