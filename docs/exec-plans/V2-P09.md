# V2-P09 — Mechanism Synthesis & Release Candidate 2

## Scope

Recompute the six mechanism cards from the V2 artifacts, publish them in English and Chinese with
their lineage, write the release bundle and the limitations report, and decide — on evidence — whether
the candidate `v0.2.0-rc1` may be tagged.

## Non-goals

- No mechanism is changed, no parameter is re-estimated, no V2-P01–P08 artifact is rewritten.
- A tag is not created by this phase when a gate is unmet; the unmet gate is published as a
  limitation instead.
- No new experiment, no new model arm, no UI work.
- No card status is moved by argument; a status moves only if a V2 artifact measures it.
- M003 is not revived and M006 is not given a rule: rejected and unidentified are outcomes.

## Acceptance

1. Every number on every card is read through an accessor from an artifact whose SHA-256 is recorded
   beside it; no V1 statistic is copied forward.
2. Every card states its V1 and V2 status, and any card that moved says which measurement moved it.
3. Every card lists its dataset, forcing, sample size, policy arm and extrapolation limits.
4. Every lineage locator resolves in the tree; a locator that does not is a hard error.
5. The gates are decided by artifact content; the tag is created only if all nine pass.
6. The release pass is deterministic: two runs produce byte-identical documents.
7. `pytest`, `ruff`, `ruff format --check`, `mypy`, `doctor`, both scenario demos and `bench` pass.
