# V2-P08 — Runtime Policy Completion

Status: **the gate was opened by constitutional amendment (ADR 0003), and the runtime layer ran.**
M2 is **not** upgraded: the runtime arm is a pilot with one decision per replicate.

## The amendment

`docs/adr/0003-runtime-model-amendment.md`. The operator instructed: keep the model id as
`deepseek-flash`, treat "`ustc-deepseek-v4.1` is the only acceptable string" as wrong, and open the
gate — choosing the amendment route over the route of reporting a `/v1/models` reading. The ADR
records that decision **as a decision**, and says in its own words that it is not a verification.

| changed | from | to |
| --- | --- | --- |
| `core/config.py` `RUNTIME_LLM_MODEL_ID` | `ustc-deepseek-v4.1` | `deepseek-flash` |
| `policies/ustc_v41.py` `FORBIDDEN_MODEL_MARKERS` | contained `flash` | `pro`, `qwen`, `glm`, `gpt`, `claude`, `opencode`, `legacy` |
| `.omp/RULES.md` rules 8 and 12 | "USTC-confirmed DeepSeek V4.1 only" | the id ADR 0003 declares, with the role-vs-string distinction made explicit |
| `docs/architecture/runtime-llm-boundary.md` | "operator-confirmed … `/v1/models`" | the declared id, and reports **must** say "declared by ADR 0003", never "confirmed" |

Two structural fixes came with it, both without which the amendment would have been inert:

- **the `.env` the operator edits is now read.** Nothing in the package loaded it: the runtime read
  `os.environ` only, so setting `USTC_LLM_ENABLED=1` in `.env` changed nothing. The policy reads
  `.env` underneath the process environment (an exported variable still wins), and the live suite and
  `doctor` read through the same function, so the three cannot disagree.
- **`doctor` reports an enabled layer as a declared state** (warning), not as an environment error —
  with the sentence that it must never hold on a compute node.

The exact-match fence is unchanged in strength: `deepseek-flash-neighbour`, `deepseek-v4.1-pro`,
`ustc-deepseek-v4.1`, `ustc-deepseek-v4.1-flash` and `deepseek-flash-v2` are all refused, because the
confirmation check admits exactly one string regardless of the marker list.

### The anonymisation audit

The corpus's prompts are rendered by `render_prompt` and audited by `audit_prompt`, which refuses a
prompt that names a place, a dynasty, a person or a year-like token. All six pass, the corpus covers
the declared triggers exactly (a trigger added to the layer without a corpus entry fails the audit),
and the corpus measures carry no name that encodes a time or a place. The observation payload carries
no tick, no date and no calendar field: the tick is recorded in the trace and never shown to the
actor, because an actor that can count months from a date can count its way to the outcome.

### Fail-closed, observed rather than asserted — and no imputation

The historical-core run presents **one decision prompt the corpus does not cover**, and the runtime
arm refused it: `0 decisions, 1 refusal`, with the state left alone. Two things follow, and the
second is a finding rather than a footnote:

- the acceptance's "fixture miss fails closed" happens in a real run: nothing was invented, and the
  arm contributed nothing to the run's outcomes;
- **the corpus does not cover the historical core**, so the runtime arm made no model decisions there
  at all. Closing that gap needs one more recording pass over the core's own seats — a live call this
  pilot did not spend — and until then the arm is a pilot with a refusal in it, which is why M2 is not
  upgraded on it.

The earlier version of this run wired a `RulePolicy` fallback under the model-backed arms, so a
refused decision came back as a *rule* decision with `outcome="fallback"`. That is imputation into the
arm the model was supposed to be tested on, and the review caught it: the fallback is now `None` for
every arm, the per-decision traces and refusals are written beside the arms
(`policy-arm-traces.parquet`, `policy-arm-refusals.parquet`), and the counts above are read from
them rather than from a summary.

## Cost and the limits of this evidence

- **≈2.8s per call**, 16.8s for six; the live suite's 21.6s includes a full round trip.
- **The runtime arm is a pilot, and M2 is not upgraded.** One decision per replicate, two replicates:
  that is far below the V2-P07 arm ladder (16 → 32 → 64), so no interval and no direction-stability
  claim is available, and none is made. The mechanism readings were identical across all four arms
  (inversion 0, ratchet 0, consolidation 1), which is what a single decision can produce and not
  evidence about a model.
- **Schema refusal, timeout and 429 were not exercised against the live endpoint** in this pilot. They
  are covered offline by the stub-transport tests (`tests/policies/test_institutional_policy.py`,
  including a 429 with `Retry-After`), and the report says which is which rather than implying a live
  observation.
- **No fallback ran, and none exists.** The only route to a model is `policy_from_environment`, which
  admits one id; a refused arm is excluded from every verdict rather than imputed.

## Independent review

Verdict: **approve-with-followups**, and the follow-ups were done before the commit.

- **MAJOR — the "declared, not confirmed" distinction was contradicted in code.** Six docstrings
  still said the id was operator-confirmed against `/v1/models`. Fixed in `ustc_v41.py` (three),
  `base.py`, `institutional_smoke.py` and `policy_robustness.py`, and
  `docs/architecture/system-overview.md` still named the **old** id — a reader following it would have
  been refused. Fixed to the declared id.
- **MAJOR — the endpoint was not fenced at all.** `USTC_LLM_BASE_URL=https://attacker.example/v1` was
  accepted, and an empty one was accepted too, with the credential read before the failure. Fixed:
  `_declared_base_url` refuses a non-https URL, an empty one, and any host that is not the declared
  USTC host — all **before** the credential is touched, with a test that fails if it is.
- **MAJOR — a rule fallback was imputed into the model arm.** Fixed as above; `fallback=None`.
- **MAJOR — the arms artifact had no producer.** Fixed: `experiments/runtime_arms.py` runs the four
  arms on the historical core, writes the arms, the traces and the refusals with a manifest (fixture
  digest, seeds, window, scenario) and the statement that no fallback runs.
- **MAJOR — the artefact counts were unprovable and the model decisions were not what the report
  said.** They now come from the kept traces, and they say something different and worth knowing: the
  arm made **no** model decisions on the core.
- **MAJOR — the anonymisation audit is a denylist, and the report claimed a guarantee.** The report now
  says what it is: 23 enumerated tokens plus a year pattern, refusing what it names and *not* claiming
  to catch every identity or date. The probe that passed `Fengyang`/`Lu Xiangsheng`/`明朝`/`Wanli`/a
  1449 date is recorded as the limit it is.
- **MINOR, fixed**: the seat's region now reaches the actor as an opaque code (`R1`…) while the node id
  stays for the lever lookup and the trace — the smoke scenario's own region labels were on the
  denylist, so every smoke prompt had been refused; the fixture count is corrected (seven files: six
  from the corpus and one from the live suite, which writes into the same store on every live run and
  will need a deliberate delete if the answer ever changes).
- **Confirmed by the review**: the exact-match fence admits only `deepseek-flash` and refuses case,
  whitespace, zero-width and near-miss variants; every fixture's filename equals its prompt hash and
  its response hash matches its content, with no credential-shaped string in any of them; a misnamed
  fixture is refused.

## Open items

- **The runtime arm needs replicates before it can say anything.** The next run on this gate should
  use the declared arm ladder, or report itself as the pilot this one is.
- **The amendment is a decision, not a confirmation.** Every report citing the runtime model must
  cite ADR 0003; a later phase that wants a verified id should record the `/v1/models` reading and
  supersede the ADR rather than quietly editing the constant.
- **The fixture corpus is six prompts.** A run whose observations fall outside it refuses, by design;
  widening the corpus is a task for the phase that needs the wider coverage, and the refusal count is
  the measure of how far outside it a run went.
