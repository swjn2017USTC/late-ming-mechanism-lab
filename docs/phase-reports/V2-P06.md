# V2-P06 — Calibration V2

Status: complete, and **non-converged by its own gates**. Run against `docs/exec-plans/V2-P06.md`.
No V2-P07 work started, and the hold-out has not been scored.

## What was done

### 1. Only evidence-backed, identifiable parameters

The priors are exactly the parameter cards' ranges, which is V1's rule kept rather than reinvented:
a parameter has a prior exactly when its card carries a numeric range, and that range *is* the
support. An `S`-grade parameter with no range is therefore not in the table and cannot enter through
a wide prior; the registry's own invariant fails if a live parameter has no card. The frozen
artifact records the prior digest, the objective digest and the evidence digest, so a later edit to
any of them changes the posterior's identity.

### 2. Process seeds, not one weather sequence

`SeedConditionedSimulator` evaluates one draw under a declared **process** seed set
(`20260915…20260918`) and reports the conditional distribution — mean, worst and per-seed — rather
than a single number. The **fixed-CRN** mode is kept as the declared contrast the phase asks for, and
the module refuses to call a one-seed set process uncertainty: one seed is common random numbers, and
that is what V1 was reporting as a posterior. The cache is keyed by *(draw, seed)*, so a hit can
never return another seed's distance.

### 3. A ladder, not one rung

Eight rungs ran: two sizes (4 and 8 particles) × four sampler seeds, two tempering stages each, four
process seeds, on a 72-tick toy window. The sampler is a sequential importance population with
systematic resampling and a bounded random-walk move, so acceptance, ESS and the duplicate fraction
are computed here rather than inside a library.

### 4. Diagnostics in the manifest

`outputs/v2/p06/posterior.json` records: process seeds, sampler seeds, mode, the gate bounds, every
rung's particles, sampler seed, weights' ESS, ESS per particle, acceptance per stage, stages,
duplicate fraction, simulation count, cache hits, seconds, failed-task list, posterior location and
the mechanism prediction; plus the prior, objective and evidence digests and the `posterior_hash`.

### 5. The stop rule, and its verdict

| gate | bound | this pilot |
| --- | --- | --- |
| location change between rungs | < 0.10 of the prior range | **0.449 — failed** |
| mechanism prediction change | < 0.05 | not measured (the probe was not read) |
| ESS per particle | ≥ 0.30 | 0.999 |
| acceptance | in [0.05, 0.95] | **1.000 — failed** |
| duplicate fraction | ≤ 0.30 | 0.000–0.063 |

**Verdict: non-converged.** The posterior's weighted median moved by nearly half a prior range
between the two rungs, and the jitter's acceptance sat at its maximum. No parameter is labelled
`identified`, and the document says in its own words that the three healthy-looking diagnostics are
statements about one rung's mechanics rather than about convergence.

### 6. The hold-out is still shut

`outputs/v2/p06/posterior.json` carries the freeze hash `ce3bd36a91d6c1e76793b05ee439ec361ee16c9278f209d64e5a640de125795a`,
and `assert_holdout_allowed` refuses any caller that does not name it — and refuses one that names a
different hash just as firmly, because a score against another posterior would belong to a different
experiment. The hold-out and extrapolation windows have **not** been scored, and they will not be
until a ladder converges and freezes.

### 7. Batch and HPC

The pilot ran locally (17 minutes of wall clock across 8 rungs, 576 sandbox runs). The batch path
`late-ming-lab batch` remains the declared route for a larger ladder: a compute node carries no
network, no API key and no runtime LLM, and the failed-task rule is inherited from V2-P04 — a failed
evaluation is recorded in the rung's `failed_tasks` and **never merged as a particle** (the sampler
gives it an infinite distance rather than dropping the row).

## Independent review

Verdict: **reject, then fixed** — one blocker, three majors, four minors. Every one was addressed
before the commit, and the pilot was re-run so that the frozen artifact is reproducible from the tree.

- **BLOCKER — the isolation gate was not wired into anything.** `assert_holdout_allowed` and
  `load_frozen_posterior` were called only by their own tests, and the reviewer scored a hold-out and
  an extrapolation window from a bare root with no freeze at all. Fixed: `run_posterior_predictive`
  now requires the frozen posterior's hash and refuses before a run starts, the `calibrate` CLI reads
  the frozen hash and passes it, and the integration test writes the freeze its batch needs rather
  than being exempted.
- **MAJOR — NaN satisfied the gates, and the prediction gate was dead.** `run_rung` discarded the
  probe and stored a NaN prediction, so `prediction_change` was always `null` and the gate could never
  fail. Fixed: the probe is now measured — the declared statistic is read from a real run at the
  rung's own posterior location — and the gate refuses a non-finite location, a non-finite change and
  an unmeasured prediction.
- **MAJOR — ESS and the duplicate fraction were vacuous.** ESS was computed after the weights were
  reset to uniform (so it was always `particles`), and duplicates after the jitter (so they were
  always zero). Fixed: ESS is measured on the tempered weights before resampling, duplicates on the
  resampled population before the jitter. The artifact now shows ESS 0.9988–0.9999 and duplicates up
  to 0.063 — numbers that can move.
- **MAJOR — `stages` was missing from the artifact and the artifact was stale.** The frozen file had
  been written by an earlier revision, so its hash could not be regenerated from the tree. Fixed: the
  rung record carries its stages, the ladder and the prediction statistic are in the freeze, and the
  pilot is now a driver (`late-ming-lab experiment p06`) rather than a hand-run script. The hash is
  `ce3bd36a…`, produced by that command.
- **MINORS**: the freeze no longer contains bare `NaN` literals (an unmeasured prediction is `null`);
  `_evaluate` records a malformed draw instead of letting a `KeyError` kill the rung; the document's
  honesty paragraph now explains all three diagnostics correctly, including why acceptance is 1.000
  (a piecewise-constant objective over a bounded prior). Two pre-existing registry notes the reviewer
  raised — a card whose central value sits outside its own range, and nineteen range-carrying cards in
  neither the declared nor the excluded list — are recorded as open items rather than touched here.

## Open items for V2-P07 and later

- **The ladder did not converge, and that is the phase's result.** A larger rung is the next step,
  and the gates — not a particle count — decide when to stop.
- **The mechanism prediction gate is measured but degenerate at this window**: `largest_band_share_end`
  is 0.0 at every rung on a 72-tick toy run, so the gate compares 0.0 with 0.0. It is no longer dead
  code — the probe runs and the gate refuses a non-finite value — but a statistic that never varies
  cannot discriminate, and the next phase should read it on a window where the band chain moves.
- **Acceptance at 1.000 is a symptom, not a health signal.** The move kernel is too wide for the
  tempered weight at this size; tightening it is a declared change to the sampler, not a tuning of
  the posterior, and it belongs in the next phase with the gates re-declared.
- **Two pre-existing registry notes**: `EliteParameters.interest_rate_monthly` has a central value
  outside its own card range, and nineteen range-carrying cards are in neither the calibration
  declaration nor the excluded list. Both predate this phase; neither was touched here.
- **The fixed-CRN contrast has not been run yet.** The mode exists and is refused a one-seed set as
  process uncertainty; the contrast experiment itself is V2-P07's.
