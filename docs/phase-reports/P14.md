# P14 - Visualization / HPC / Release Candidate

Date: 2026-09-14
Status: complete, tagged `v0.1.0-rc1`. No P15 exists.

## Scope

Make the model runnable, observable and portable to HPC **without changing a core mechanism**. P14
adds surfaces over what P01-P13 produce: a command line, an artifact browser, a batch and Slurm
layer, environment checks, a measured benchmark, and a declared demo scenario whose digest a
regression test reproduces.

Non-goals, held to: no new mechanism, rule, parameter or tick-order entry; no LLM on a compute node;
no API key anywhere near the batch layer; no network requirement on a node; no new dependency; no
configuration file for a threshold a constant can state.

### Acceptance criteria

```text
run · replay · experiment · calibrate · analyze · doctor · bench · batch · ui
a Solara app serving the artifact views, the comparison and the card browser
a declared demo scenario reproduced by a regression test
a benchmark compared against declared dev thresholds, with a profile
a Slurm array template whose bounds, seeds and time limit come from the plan
doctor: uv.lock/pyproject/python/secret checks that fail closed
a merge that never imputes a row for a task that did not run
README: quick start · architecture · epistemic warning · reproduction · HPC guide
full review · full suite · clean tree · tag v0.1.0-rc1
```

## HPC principles, and how each one is enforced rather than described

```text
compute nodes need no network       tests/unit/test_batch.py imports the module and inspects
                                    sys.modules for httpx/openai/ustc; the check is a subprocess
                                    probe, so it cannot pass on an already-imported module
no API key is uploaded              env_checks names a credential-shaped variable and never prints
                                    its value; the Slurm template exports USTC_LLM_ENABLED=0
no USTC runtime LLM on HPC          the template's header states it and the script sets the switch;
                                    a batch task for the p12 family records the refusal, not a row
recorded online, replayed offline   experiments/replay.py: declared settings, no credential, no
                                    environment lookup, no fallback, and it fails closed on a miss
every task has its own seed         TaskSpec.seed == base_seed + index, written into that task's own
                                    manifest; the plan refuses a family it does not know
a failed task can be re-run         tasks are built in a temporary directory and renamed into place,
                                    a raising task writes failed.json only, and a re-run replaces it
```

The two families that cannot be reduced to a single task — `sobol` and `tipping`, whose parameter
sets come from a completed Morris elementary-effects table — are refused by `plan_batch` with the name
of the missing step rather than faked into one.

## Performance thresholds

Measured on the development machine (Apple M4, Python 3.12.14, medium sandbox, 240 ticks, seed
20260915):

```text
seconds              9.87
ticks per second     24.3
peak resident        898 MiB
events               242,979
```

Declared, and enforced by `bench --enforce`:

```text
dev-throughput   >= 5 ticks/s      a developer's edit-run loop: a full window under a minute
dev-window       <= 120 s          one full-window run inside a short interactive session
dev-memory       <= 2048 MiB       a laptop running the model beside an editor and a browser
```

Declared as a cluster budget rather than a grade (no cluster was available to this phase, and the
phase says so):

```text
hpc-per-task     <= 600 s          one array task inside a ten-minute walltime, safety factor 1.5
hpc-memory       <= 4096 MiB       the per-task ceiling a shared node enforces
```

The Slurm renderer takes the operator's walltime ceiling and refuses to render when the estimated
per-task cost (measured seconds × safety factor) does not fit it; the rendered `--time` is that
estimate, floored at one minute because schedulers reject a sub-minute limit outright.

## Independent review

`P14Review` (read-only) tried to falsify all five claims, including against real batches it built in
`/tmp` rather than the stubbed tests. Verdict: **approve with follow-ups** — "the mechanisms are
untouched and the batch/HPC/demo/benchmark claims hold under falsification". What it verified:

- **No mechanism change**, from `git status`/`git diff`: only `README.md`, `cli.py`,
  `experiments/institutional_smoke.py` and `tests/unit/test_cli.py` are modified, and the
  `institutional_smoke.py` diff is exactly the optional `settings` plumbing whose default path is
  byte-for-byte the previous behaviour. No parameter value differs anywhere.
- **The demo reproduces**: its own run printed the digest recorded in the scenario file.
- **The benchmark is honest**: it re-measured 9.79 s / 24.5 ticks per second / 898 MiB, so the declared
  dev bounds have 12×, 5× and 2.3× headroom — clearable on a much slower machine, which is what a
  threshold has to be.
- **The batch rules hold** against a real 13-task batch and a sabotaged one: per-task seeds recorded
  in each manifest, a completed task skipped with an unchanged digest, `failed.json` written without
  disturbing the plan, and a merge that recorded `failed: [0,1]` / `missing: [2..31]` / `merged: []`
  and wrote no `runs.parquet` at all rather than inventing rows.
- **The import-graph test is real**: it spawns a subprocess, imports the module and inspects
  `sys.modules`, rather than asserting something already true in the test process.
- **The Slurm path**: array bound = task count − 1, time limit = measured cost × safety, the refusal
  fires when the declared ceiling is too small, and the header states the four HPC rules.
- **`doctor`**: nine findings, all real, and the credential check reads presence and never the value.
- **The CLI surface**: nine commands, no `smoke-run` alias left anywhere, `experiment` refusing an
  unknown family with the known ones named.

The findings, and what the phase did about them:

| severity | finding | resolution |
|---|---|---|
| MAJOR | `analyze` refused every run directory: it required `events.parquet` while the run store writes `agent_events.parquet`, and the only run-layout test hand-wrote the wrong name | the check accepts either name and the refusal names both; the test now writes a real run through `SimulationKernel` + `RunStore`, so it fails on the old code |
| MAJOR | importing the browser pulled the whole experiment chain, transport included (`ui.data -> synthesis.report -> synthesis.evidence -> experiments -> policies.ustc_v41 -> httpx`) | `load_book` and the card path constants moved into `synthesis.schema`, which imports only pydantic and yaml; the probe now shows no `httpx`, `openai`, `ustc` or `experiments` module in the browser's import graph |
| MINOR | `batch <unknown-action>` reported the missing `--plan` before the unknown action | the action is validated first |
| MINOR | a missing plan printed a traceback instead of the one-line failure its siblings print | `FileNotFoundError` is caught with them |
| MINOR | `ui` addressed the app by a repository-relative `src/` path, so it would not work from a wheel | the path resolves inside the installed package |

**One structural note recorded rather than fixed.** The browser still pulls `analysis.distress`
transitively, which imports the coping-stage and cohort-event vocabularies from `actors` at *runtime*
(not only for annotations), so `late_ming_lab.actors.*` and `late_ming_lab.core.*` remain in its
import graph. Decoupling that means moving a P03 vocabulary constant, which changes a tested module
for no behavioural gain; the release-relevant half — no transport, no kernel, no experiment runner in
the browser process — is fixed, and the remaining coupling is recorded here as a follow-up rather
than smuggled into a release-candidate commit.

## Changes to earlier phases

- **`smoke-run` became `run`.** The old name is gone rather than aliased, and `tests/unit/test_cli.py`
  was migrated with it: seven tests now drive `run`, including the two that pin reproducibility
  through the CLI.
- **`build_policy` and `run_institutional` accept declared settings.** The replay path needs settings
  it can construct without reading the environment or a credential; the live path is unchanged and
  still goes through `load_settings`.
- **The Slurm renderer floors the job's time limit at one minute**, so a cheap plan does not render a
  script a scheduler rejects.
- No mechanism, parameter value, rule or tick-order entry changed anywhere.
