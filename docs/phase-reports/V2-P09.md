# V2-P09 — Mechanism Synthesis & Release Candidate 2

Status: complete, and **the candidate is not tagged**: three of the nine cross-phase gates are unmet
and are published as limitations instead. Run against `docs/exec-plans/V2-P09.md`.

## What was built

`src/late_ming_lab/synthesis/v2.py` recomputes the six cards from the V2 artifacts and writes every
release document; `src/late_ming_lab/release/bundle.py` decides the nine gates from the plan's §7 and
binds the bundle. One command produces all of it:

```bash
uv run python -m late_ming_lab.release v2
```

| element | what it is |
| --- | --- |
| `build_cards` | one `_mNNN` per card, each reading its numbers through a typed accessor |
| `EvidenceRef` | a statistic, the accessor that read it, and the artifact's SHA-256 |
| `LineageStep` | source → normalized row → parameter/rule → run → statistic → card |
| `unresolved_locators` | a lineage locator naming a path the tree lacks is a hard error |
| `data/mechanisms/v2-zh.yaml` | the Chinese translation table: data, not code |
| `evaluate_gates` | the nine gates, each decided by artifact content rather than by a file existing |
| `build_release_bundle` | commit, lock, artifacts, reports and translation version, each hashed |

`docs/v2/limitations-v2.md` states this in full and the tag `v0.2.0-rc1` is **not created**; `git tag -l`
lists only `v0.1.0-rc1`. That is the phase's central decision: a release candidate that hides an unmet
gate is worse than one that does not exist.

## How the bundle binds, and what that means

| field | what it answers |
| --- | --- |
| `code_digest`, `code_files` | which code produced these documents, by content: one hash over the package's 156 sources, so a checkout at any commit produces the same digest |
| `git_sha`, `tree_dirty` | where the tree was, and whether it carried uncommitted changes; the bundle's own path is excluded, so two consecutive passes agree |
| `artifacts`, `reports`, `uv_lock_sha256`, `pyproject_sha256` | every input and every generated document, by SHA-256 |
| `gates` | the nine verdicts with the evidence that decided each |
| `bundle_hash` | the whole manifest, so a rebuilt bundle that differs anywhere is visibly different |

A rebuild after a later commit updates `git_sha` and `tree_dirty` and nothing else — the code digest
and every artifact hash stay put — so the one field that moves is the one that is *supposed* to say
where the tree was. That is the whole residue of the self-reference problem, and it is visible rather
than hidden.

## Two defects in this phase's own work, found by checking the artifacts

The bundle's `tree_dirty` field was computed from an unfiltered `git status --porcelain`, so it
counted the bundle itself: a first pass on a clean tree wrote `false`, and a second pass — finding
nothing changed but the file it was about to write — wrote `true`. Two consecutive passes therefore
produced different bytes, which is the one thing the release pass must not do, and the determinism
check is what exposed it. The bundle's own path is now excluded, and a test runs the pass twice and
asserts the flag does not move.

The first bundle written by this phase named the parent commit with `tree_dirty: true`. That is
accurate about the moment of generation and useless to a reader: the parent does not contain the
synthesis module the bundle describes. It is regenerated on a clean tree, so `git_sha` names the
commit that carries the generating code.

## A defect found and fixed outside the synthesis

`tests/integration/test_policy_robustness.py::test_a_small_real_batch_writes_an_artifact_its_report_can_be_rebuilt_from`
failed with `polars SchemaError: type String is incompatible with expected type Null` on `model_id`.
The cause was real and not in the test: an arm that calls no model writes `None` into every `model_id`,
so polars inferred `Null` for that column, and stacking it beside an arm that did call a model failed
on a `String`/`Null` mismatch. `institutional_smoke.py` now builds every trace frame through one
declared `TRACE_SCHEMA`, which fixes the stacking rather than the assertion.

## What the release does not claim

- **Model support is not historical truth.** Every card separates `model_evidence` from
  `historical_support`; a status is a statement about this model under a declared configuration.
- **Failed, rejected and unidentified are results.** M003 stays rejected and M006 stays unidentified,
  and the unmet gates are printed rather than argued away.
- **The historical core's own gate contrast has not been run.** M002's arms are the V2-P03 pilot's on
  the toy space; the card says so in its `applies_to` and in its uncertainty.
- **The Chinese cards are a translation of the English originals, at a declared version.** Locators,
  digests and statistics stay in their source form, and the file says why.
