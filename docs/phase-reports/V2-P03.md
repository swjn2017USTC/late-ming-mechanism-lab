# V2-P03 — Outcome & Validation Protocol

Status: complete. Run against `docs/exec-plans/V2-P03.md`. No V2-P04 work started.

## What was done

V1's verdicts were read off eight declared governance thresholds and reported through one derived
number, `breakdown`. The phase freezes what an outcome *is* before any V2 result exists, so that the
next phases argue with definitions rather than with whichever line was in force.

### 1. The protocol, and its identity

`data/protocol/validation-protocol-v2.yaml`, loaded and refused by
`src/late_ming_lab/protocol/schema.py`.

- Version `2.0.0`, digest `788458c441a8ce9fbe51405a4134877a9c4b01c4f6d8fccda7c26ea04c11b801`, status
  `frozen`. The digest is the SHA-256 of the canonicalised content: no clock, no path, no seed.
- **Nine primary outcomes over the seven dimensions the phase names** — fiscal realisation, fiscal
  base, fiscal arrears, relief coverage, military supply, migration outflow, market connectivity,
  livelihood shortfall, armed concentration — each with a direction, a prose aggregation, a
  machine-readable `form` (`measure` / `ratio` / `vector`), the measured quantities it is read from,
  a minimum substantive effect, and the strongest comparison level the record supports (`direction`,
  `ordering`, `magnitude`, `none`).
- **`breakdown` is a derived reading.** `crossed_lines` and `breakdown` live under
  `derived_readings`; `breakdown` carries its own line (`breakdown_min_crossed` = 6, model-assumption,
  range `[4, 8]`) and the report is required to take it at every value in that range.
- **Windows.** Calibration 0–119, hold-out 120–215, extrapolation 216–239 tile the 240-tick run;
  whole-run is a *reporting* window and is never a fitting target. Missingness defaults to `refuse`,
  so an unmeasured quantity is a refusal rather than a zero.

**Seven intermediate series**, declared under `intermediates:` and produced by
`protocol/intermediates.py`: the fiscal, military, armed-band, migration, trade-link and sampled
governance quantities at the county, the month or the link, so a mechanism chain is retained and not
only its end state. A series with no rows is returned empty — nothing moved in that run — while a
series nothing produces, or a declared field its frame lacks, is refused.

`protocol/measures.py` binds each outcome to quantities a run actually produces — the existing
`outcome_scalars` plus the subsistence need, unmet need and relief released that the protocol names —
with `tests/unit/test_protocol_outcomes.py` holding the protocol to names the measure set really has.

### 2. Isolation and fail-closed batches

`protocol/freeze.py`. `PURPOSE_WINDOWS` is the single place that says which purpose may read which
window: `fit` may read calibration only, `score` may read hold-out and extrapolation only, `report`
reads everything. A batch carries `validation_protocol: {version, digest}`; `assert_batch_protocol`
refuses a batch that records a different digest, a different version, **or no protocol at all**.

### 3. The threshold ensemble

`data/protocol/threshold-ensemble-v2.yaml` and `protocol/thresholds.py`. All eight lines, each with
the live value, a declared band, what the band rests on, its identity (`model-assumption` for all
eight: the V1 cards carry no ledger claim, and the file says so rather than upgrading them), and its
sampling rule. The design is enumerated whole — 5⁴ × 3⁴ = **50,625 members** — so no report can be
accused of picking a favourable member.

### 4. The model-comparison register

`data/protocol/model-comparison-register-v2.yaml` and `protocol/comparison.py`: eight pre-registered
comparisons, four for V2-P04 (price formation, relief bottleneck, migration structure, climate
forcing) and four for V2-P05 (famine mortality, elite mediation, band consolidation, arrears
persistence), each with candidate structures, a prior expectation, discriminating observables drawn
**only** from the protocol's primary outcomes, and a falsifier. Every one of the nine outcomes is used
by at least one entry; a missing theme fails the load.

### 5. The robustness report

`protocol/{robustness,evaluation,report}.py`, generated into `docs/v2/threshold-robustness.{md,json}`
by `late-ming-lab protocol robustness`. For each mechanism card it reports the share of ensemble
members under which the card's criterion **holds**, **changes**, or is **undetermined**, at every
crossed count the protocol allows (4…8).

The evaluation set is a declared pilot: `BASELINE`, `OPEN_MIGRATION_EXIT` and `NO_ELITE_CREDIT` at
four seeds, 240 ticks, base seed 20260915, written to `outputs/pilot/v2-p03/` (gitignored) with each
run's log, manifest, summary and measures. **It is not a result**: it fits nothing, its arms are the
sandbox's scenarios rather than the historical core, and its numbers appear only as measurements a
threshold was applied to. Its purpose is that the ensemble move something real, and that the runs stay
re-scorable from disk (`report.load_pilot_runs` re-measures them with the same function that measured
them at run time).

## Results

Twelve runs, 50,625 members, 8 criteria × 5 breakdown lines. The headline numbers, from
`docs/v2/threshold-robustness.json`:

| criterion | reads a line | holds | changes | undetermined |
| --- | --- | --- | --- | --- |
| `M001.policy-dependent-inversion` | no | 0.000 | 0.000 | **1.000** |
| `M002.breakdown-in-every-arm-replicate` | yes | 0.461 | 0.539 (at line 6) | 0.000 |
| `M002.base-contraction-separates-arms` | no | 1.000 | 0.000 | 0.000 |
| `M003.ratchet-absent-in-the-reference-arm` | no | 1.000 | 0.000 | 0.000 |
| `M003.ratchet-present-with-the-gate-open` | no | 1.000 | 0.000 | 0.000 |
| `M004.lending-fires-and-stops-firing` | no | 1.000 | 0.000 | 0.000 |
| `M005.consolidation-reading` | no | 1.000 | 0.000 | 0.000 |
| `M005.above-declared-share-line` | yes | 0.400 | 0.600 | 0.000 |
| `M006.famine-mortality` | no | 0.000 | 0.000 | **1.000** |

- **M002's status is not threshold-free.** "Every gate replicate breaks down and no baseline replicate
  does" holds under 46.1% of members at the protocol's declared line of six, and its share runs
  0.000 / 0.178 / 0.461 / 0.206 / 0.026 across the allowed range 4…8. Below the gate's own margin the
  baseline breaks down too; above it the gate does not. The card's SUPPORTED status is a statement
  about the model *and* about the line, and V2-P04 has to carry that.
- **M005's share claim moves**, 0.400 / 0.600: it asks whether the largest band exceeds the line.
- **The measured part of M002 does not move.** The gate arm's tax-base contraction exceeds the
  baseline's in every replicate of every member — the contrast survives the whole ensemble, which is
  what makes the failure at the line readable rather than fatal.
- **M003 shows both** its status and its counterexample: the ratchet reading is absent in all four
  reference-arm replicates (the rejection reproduces) and present in all four gate-arm replicates,
  with the migration gate open. Both are threshold-free, so the ensemble reports them as invariant.
- **Two criteria are undetermined for stated reasons, not for convenience.** M001's status is a
  contrast across decision policies and the pilot runs one; M006's chain has no mortality channel to
  measure at all. Neither is a threshold question, and neither is reported as decided.
- Per-arm breakdown shares at the declared line of six: baseline 0.232–0.344, `NO_ELITE_CREDIT`
  0.168–0.344, `OPEN_MIGRATION_EXIT` 0.810–0.904. The gate arm's separation is large; the threshold
  question is whether *any* baseline replicate crosses, and in most members one does.

Three bugs the tests caught while the phase was being built, all now fixed and pinned:

1. `protocol_measurements` never exposed `relief_released_shi`, which the protocol names: the outcome
   vector refused every run. The measure set and the protocol are now held together by a test.
2. The crossed-count histogram summed over runs, so it reported 51…88 crossings for runs that can
   cross at most 8 lines. It now counts one (member, run) pair at a time, with a test on the bound.
3. The outcome vector aggregated by matching prose ("ratio of …"), so `migration_outflow`'s "ratio of
   window totals; minimum net node flow" was read as a ratio and refused every run. The protocol now
   declares a machine-readable `form` per outcome, with ratio outcomes required to name exactly two
   measurements.

## Independent review

An adversarial reviewer (`reviewer`) worked from the tree rather than from this report. Verdict:
**approve-with-followups**, no blockers, two majors, three minors. Its checks and what came of them:

- **The single-threshold flip (the phase's own test of itself): it flips.** From a member that holds,
  moving one line inside its declared band — `largest_band_share` 0.2 → 0.35 — takes
  `M002.breakdown-in-every-arm-replicate` from holds 1.000 to changes 1.000 at the declared crossed
  count of six; `pay_shortfall_share` and `unmet_share_of_need` do the same within their bands. The
  reverse does not hold: from a changing member, no single in-band move of any line restores it. The
  criterion is easier to break than to satisfy, which is the finding the phase exists to produce, and
  it is reported rather than avoided by choosing a member.
- **Invariance of the threshold-free criteria: confirmed.** Seven criteria × eight lines × 41 points
  across each declared band, 2,296 evaluations, zero verdict changes.
- **The undetermined rows are honest**: M001 names a policy contrast the pilot does not contain (all
  three arms run the same extraction policy), M006 names a chain with no mortality measurement at all.
- **The pilot is not presented as a result**, and the committed report recomputes exactly from the
  twelve stored runs.
- **No threshold is written as a historical fact**: all eight entries are `model-assumption`, every
  band is declared around the live line, and the schema refuses a value outside its band.

Two integration gaps it found, both now closed rather than deferred:

1. **Nothing actually fail-closed**: `assert_batch_protocol` and `stamp_batch` had no caller outside
   the tests, and no real artifact carried a protocol digest. Each pilot run now carries
   `validation-protocol.json`, written by the pilot itself, and `report.load_pilot_runs` refuses a run
   without one or with another digest — verified by refusing the twelve unstamped runs from before the
   fix. The V1 batch writer is left alone: no V1 batch was scored under this protocol.
2. **`compute_outcomes` would measure any window for any caller.** It now takes a required `purpose`
   and calls `assert_window_access`, so the only place a window's numbers are produced is also the
   place the isolation rule is enforced — the acceptance criterion is code rather than convention.

Three minors fixed in the same pass: the generated document repeated per-line rows and could list a
moving criterion as fixed (`stable_criteria` now requires the same verdict at every allowed crossed
count, and the undetermined list is deduplicated); `IndicatorShare.line_min/line_max` were hardcoded
0.0 and are now computed and printed; M001's verdict is computed from the policies the runs actually
used instead of being a constant, so a future multi-policy pilot decides it.

One finding is deferred with its reason: **`calibration/windows.py` still hardcodes the window ticks**
independently of the protocol, so the two could drift. Binding the calibration surfaces to the protocol
is V2-P06 work, and it is recorded under open items rather than quietly dropped.

## Open items for V2-P04 and later

- **The M002 line dependence is now a result V2-P04 must carry**, not a footnote: any statement resting
  on breakdown has to name the line and the share.
- **M001's status cannot be scored from a single policy arm.** The pilot runs one; the policy contrast
  needs the P12 policy dimension, so either the protocol gains a policy axis or the criterion stays
  undetermined.
- **The pilot's own configuration is not the card evidence's configuration** (the baseline arm carries
  the declared escalation and disruption regimes). A criterion evaluated on the pilot is a statement
  about the pilot; re-adjudicating a card needs that card's own arms under the frozen protocol.
- **The intermediate series are produced on demand and are not yet persisted as documents.** They are
  re-derivable from every retained log, and the protocol now names them; writing them per batch belongs
  with the V2-P04/P05 variants that will read them.
- **`calibration/windows.py` and the protocol hold the window table separately.** The calibration
  surfaces hardcode ticks 0–119 / 120–215 / 216–239 and never read the protocol; a protocol edit would
  leave them behind. Binding them is V2-P06's, and the reviewer found it.
- **The ensemble's bands are declared, not sourced** (all eight entries are `model-assumption`). Where
  a band could rest on a pattern rather than a convention, V2-P09 should say which.
