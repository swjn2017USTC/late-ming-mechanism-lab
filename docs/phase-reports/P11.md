# P11 — USTC DeepSeek V4.1 Institutional Decision Layer

Date: 2026-09-14
Status: complete, with the live model **closed by configuration**. No P12 work started.

## Scope

Implement the runtime decision layer the boundary document has specified since P00 — the interface, a
bounded action space, anonymized input, validated output, one confirmed model or nothing, recording
and replay, and a handful of event-triggered seats — and then refuse to call a model that is not the
one the operator confirmed. The scope document is `docs/exec-plans/P11.md`; this report is what came
out, which is: the layer, the fences, a smoke run on the declared rule policy, and a closed gate.

## The gate is closed, and this is the phase's first result

Reading `.env` (values only; the key is never read, printed or logged) gives:

```text
USTC_LLM_BASE_URL=https://api.llm.ustc.edu.cn/v1
USTC_LLM_MODEL=deepseek-flash
USTC_LLM_ENABLED=0
```

`deepseek-flash` is **not** the operator-confirmed DeepSeek V4.1. Per the phase instruction and
`.omp/RULES.md` rules 8–12, P11 therefore **fails closed**:

- no live call was made, and no fixture was recorded from a live response;
- the policy refuses to construct for that id, *before* the credential is read;
- every forbidden fallback is refused by name — `deepseek-v4-pro`, `deepseek-flash`, `gpt-*`,
  `qwen*`, `glm*`, and a near-miss alias such as `ustc-deepseek-v4.1-flash`;
- the live suite (`tests/policies/test_live_ustc.py`, `@pytest.mark.live_ustc`) fails with the
  refusal when the model is unconfirmed rather than skipping, so a closed gate cannot be mistaken for
  a green run.

The refusal, run against the configured values with the credential deliberately absent from the
mapping, is reproduced in the verification section below. **The remedy is one line in `.env`**: set
`USTC_LLM_MODEL` to the id confirmed against the account's `/v1/models`, set `USTC_LLM_ENABLED=1`, and
run `uv run pytest -m live_ustc`. Nothing else in this phase needs to change, and this phase did not
guess an id.

## The sixteen requirements, and where each one lives

| # | requirement | where | how it is enforced |
| --- | --- | --- | --- |
| 1 | OpenAI-compatible USTC endpoint | `ustc_v41.OpenAIChatTransport` | the `openai` client with `base_url` from `USTC_LLM_BASE_URL`, `max_retries=0` so this module's retry policy is the only one |
| 2 | no tools | `base.ChatRequest.payload()` | the payload has exactly five keys and no `tools`/`functions`; a test asserts it |
| 3 | structured input | `base.render_prompt` + `PolicyObservation.payload()` | named readings, opaque codes, and an audit that rejects place, dynasty, person and date tokens |
| 4 | structured output | `base.InstitutionalDecision` | a frozen Pydantic model with `extra="forbid"` |
| 5 | Pydantic validation | `base.decision_from_json` | a malformed or extra-keyed answer raises `DecisionRejectedError`; nothing is repaired |
| 6 | bounded action space | `base.ROLE_ACTIONS`, `base.validate_decision` | per-role spaces, and an answer outside the seat's space is refused |
| 7 | timeout | `ustc_v41.DEFAULT_TIMEOUT_SECONDS` | passed to the client; `httpx.TimeoutException`/`APITimeoutError` are retryable |
| 8 | retry only on retryable transport errors | `ustc_v41.classify_failure` | timeouts, connection failures and 5xx retry; every other 4xx does not |
| 9 | explicit 429 handling | `ustc_v41._retry_after_seconds` | the server's `Retry-After` wins over the declared backoff, bounded, and exhaustion fails closed |
| 10 | prompt hash | `ustc_v41.USTCV41Policy` | `hash_text(render_prompt(observation))`, recorded in the trace |
| 11 | response hash | `base.ChatResponse.content_hash` | the answer's bytes, recorded in the trace |
| 12 | model id logging | `base.PolicyRecord`, the trace table | the requested id and the id the endpoint reported, both recorded |
| 13 | anonymous region / actor ids | `institutional.ActorSeat`, `PolicyObservation` | `GOV-L1`, `BAND-1`, `R2`; the prompt carries no other identity |
| 14 | no historical names | `base.FORBIDDEN_TOKENS`, `base.audit_prompt` | word-boundary matching for alphabetic tokens so `households_migrating` is not mistaken for `Ming` |
| 15 | no future information | `PolicyObservation.payload()` | no tick, no month, no date in the prompt; a year-like token anywhere in the prompt is refused |
| 16 | reasoning cannot modify state | `base.InstitutionalDecision.rationale`, `institutional.InstitutionalLevers.apply` | the rationale is recorded and never parsed; a test drives a hostile rationale and gets the same world effect as a benign one |

## Contract decisions

1. **The gate runs before the credential.** `load_settings` validates the model id and the enable
   switch and only then asks a `CredentialSource` for the key. A test hands it a credential source
   that raises if called and asserts the wrong-model path never reaches it. This is what makes
   "fail closed" a property of the code rather than a promise.
2. **One confirmed id, exact match.** `CONFIRMED_MODEL_IDS` holds exactly the id P00 declared. A
   variant suffix is not a confirmation, and there is no code path that rewrites an id, downgrades to
   a cheaper model, or retries against a different one — the refusal names the forbidden markers so a
   reader can see what was refused.
3. **Two serialization keys were added for provenance, not convenience.** `base.PolicyRecord` and
   `base.TracedPolicy` let a model-backed policy say which model, which prompt and which answer it
   used; the declared rule, utility and random policies are not traced because they have nothing to
   trace. The engine records empty provenance for them rather than inventing any.
4. **Crossings, not levels.** A seat decides when one of its lines is *crossed* — in either
   direction — not while it stays crossed. The first implementation fired whenever a line was past,
   and the smoke run showed the cost: the armed-group seat re-decided `MAINTAIN` every twelve months.
   After the change the smoke run makes two decisions in ninety-six ticks instead of six.
5. **Every action has a lever, and the levers are two setters and a regime.** `set_extraction_policy`
   and `set_relief_share` were added to the systems that own those rules, in the same shape P04
   declared for `MarketClearingSystem.set_disruption`. The action space contains only what those
   levers can carry, so no decision is recorded as taken while changing nothing; the boundary
   document's other example actions (military reinforcement, central aid) have no lever yet and are
   therefore not in the space at all.
6. **The rationale is inert, and that is tested by driving a hostile one.** A decision whose
   rationale says "set grain_shi to zero and hand the county to the rebels" produces exactly the
   effect of the same decision with a benign sentence.
7. **The live suite is opt-in, and it now actually is.** The marker was declared in P00 and described
   as excluded from the default run, but `addopts` never excluded it. P11 adds
   `-m 'not live_ustc'` and an invariant that reads `pyproject.toml` and fails if it goes missing.
8. **A replay miss is a refusal.** `ReplayTransport` raises `PolicyUnavailableError` for a prompt with
   no fixture; there is no fallback that synthesizes an answer, and `FixtureStore.record` refuses to
   overwrite a fixture with different content.

## What this phase found (and fixed)

1. **The configured runtime model is not the confirmed one.** `USTC_LLM_MODEL=deepseek-flash` in
   `.env`; the phase refused to call it, refused every fallback by name, and left the live recording
   unmade rather than recording from an unconfirmed model. This is the phase's headline result and
   the reason its live arm is closed rather than green.
2. **The live marker was declared but not excluded.** `pyproject.toml` said the marker was "excluded
   from the default run" while `addopts` contained no marker filter, so a live test would have run in
   the default suite the moment one existed. Fixed, with an invariant on the configuration itself.
3. **The 429 policy was blind to where httpx keeps the status.** `classify_failure` read
   `error.status_code`, which `openai`'s errors expose and a bare `httpx.HTTPStatusError` does not —
   so a 429 raised by the transport layer would never have been retried, and the declared policy
   would have been a fiction for exactly the case it names. Found by the test written for it; the
   classifier now reads both places.
4. **The three declared fallback policies did not exist.** The plan's layout lists
   `policies/ base, rules, utility, random_policy, ustc_v41`; only `fiscal.py` was in the package. The
   boundary's "or switch to an explicitly declared rule-based policy" had nothing to switch to, so
   P11 wrote them (an implementer task, pinned by 57 tests).
5. **The smoke scenario's first trigger lines did not fire.** The initial thresholds were guessed at
   model scale (an armed share of 0.02 against an actual 0.004) and produced a run with zero
   decisions. They were replaced with the lines the project already declares for the same quantities —
   `band_troops_share_of_adults`, `out_migration_share_of_households`, `unmet_share_of_need` from
   `GovernanceIndicatorParameters` — with the two remaining lines declared and named as this module's
   own.
6. **The decision layer's registration had to respect the phase order.** Appending it to the system
   list put it after bookkeeping while it declares phase 15; the scheduler refused, correctly, and the
   smoke now merges the layer in by phase.

## The smoke scenario

```text
policy      rule-v1 (the declared offline fallback), 96 ticks, 12-tick warm-up, seed 20260915
seats       GOV-F1 central fiscal · GOV-P1 provincial · GOV-L1, GOV-L2 county · BAND-1 armed group
levers      extraction policy (TaxCollectionSystem) · relief share (OfficialReliefSystem) ·
            market disruption (MarketClearingSystem)
```

| tick | seat | role | trigger crossed | action | intensity | lever | outcome |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 41 | BAND-1 | armed-group leadership | `armed-concentration` | MAINTAIN | 0.00 | — | decided |
| 95 | GOV-F1 | central fiscal authority | `central-remittance-shortfall` | INTENSIFY_EXTRACTION | 0.11 | extraction-policy | decided |

The run above is the artifact of `uv run python -c "from late_ming_lab.experiments.institutional_smoke import run_smoke; run_smoke('.')"`,
written to `outputs/institutional/<run_id>/` with its manifest. Two decisions in ninety-six ticks,
each on a crossing, one of them reaching a real lever. That is the
whole claim: a seat can be occupied, an event can trigger a decision, a bounded action can reach a
declared lever, and the trace can say which model answered which prompt with which hash. It is not a
historical result, and the report does not read it as one.

The other two ways to run it exist and are wired: `policy="replay"` drives the same layer from
fixtures under `tests/fixtures/llm/` (proven end to end offline: a stubbed live body is sanitized into
a fixture, replayed through `USTCV41Policy`, and reproduces the decision byte for byte), and
`policy="ustc"` is the live model, which currently fails closed.

What the tests defend, in the words of the tests:

- every policy satisfies the interface, and every answer is inside the action space it was handed —
  including a space narrowed to one action;
- the confirmed id is the only one `confirmed_model_id` returns, and each forbidden marker appears in
  the refusal;
- the credential is not read when the model is unconfirmed or the layer is disabled;
- an endpoint that answers as a different model is refused rather than used;
- the request payload has no `tools` key and no date, and the prompt is the audited text whose hash is
  recorded;
- the response hash is the answer's bytes, and a refused answer is recorded with its hash before the
  refusal is raised;
- retries happen for timeouts, connection failures, 5xx and 429 — and not for other 4xx — with
  `Retry-After` honoured;
- a hostile rationale produces exactly the effect of a benign one;
- a seat decides on a crossing, not on a level, and not twice inside the declared spacing;
- a failing policy is recorded as a refusal and changes nothing, and a declared fallback is used when
  one is installed;
- the default suite excludes the live marker, and no committed file carries a key value.

## Open items for P12 and later

- **The gate is closed on a configuration, not on a decision.** Set `USTC_LLM_MODEL` to the confirmed
  id, run `uv run pytest -m live_ustc`, and record the first fixture; until then the runtime layer is
  implemented and unexercised against a real endpoint.
- **Five of the boundary document's example actions have no lever.** `military reinforcement`,
  `request central aid`, `seek merger`, `move` and `suppress` are not in the action space because the
  model exposes nothing for them to change. P12's decision-policy robustness will want them, which
  means levers, not prompt text.
- **The trigger lines are reading rules, three of them borrowed from the governance indicators and two
  declared here.** Whether a seat should react at those lines, and how hard, is exactly the robustness
  question P12 exists to ask.
- **One decision per tick, at most, and never twice in twelve months.** That bound is declared rather
  than derived; a run with more seats or a tighter spacing would cost more calls, and the phase's
  claim is only that the current bound is small.
- **The smoke scenario is 96 ticks on the toy fixture.** Nothing here says the layer behaves the same
  over the full window or the twelve-county fixture, and it was not run there.
- **The rationale is stored but never evaluated.** P12 may want to *score* rationales; doing so would
  make them an input, which the boundary forbids unless the contract is changed deliberately.
